设计说明

星空放映厅 · 露天电影全栈排片系统 — 视觉系统、领域设计与并发工程说明。本页全部为原创排版。

一、视觉概念：夜幕放映

露天电影的核心意象是「一束光划破夜色」。整站以夜幕墨蓝为底，放映机琥珀为主强调色， 首屏用锥形渐变模拟放映机光束，背景星空由多层径向渐变纯 CSS 绘制，零图片素材。 业务秩序感由两枚隐喻承载：票根（场次卡片两侧的打孔缺口、回执的锯齿副券）与印章（状态徽章做 2° 倾斜的盖章处理）， 让「改期 / 取消 / 满额」这类运营状态一眼可辨。

  • 回执：页面唯一的米白区块，模拟纸质票根，右侧副券印斜纹。

四、状态机

场次

scheduled ──改期──▶ scheduled(时间已换, reschedule_count+1, booking_frozen=1) ──解冻──▶ 恢复报名
scheduled ──容量满──▶ full（派生态：confirmed ≥ capacity，列表直接显示「满额」）
scheduled ──取消(人工/天气预案确认)──▶ cancelled（终态，迟到天气更新不再改变）

座位生命周期

free ──占位──▶ held(active, ≤120s) ──确认──▶ taken（hold→consumed，reservation→confirmed）
held ──超时/放弃──▶ expired/released ──▶ free
confirmed ──缩减容量溢出──▶ displaced（列入待处置名单，保留 confirm_seq 证据）
confirmed ──改期 rebook 政策──▶ rebook_pending（座位释放，等待观众重订）

天气预案（双人确认）

天气数据注入 ──▶ pending（仅内部可见，公开状态不变）
pending ──运营确认──▶ confirmed → 执行 取消场次 / 顺延（老票迁移）
pending ──运营驳回──▶ rejected
任何迟到/重复数据 ──▶ superseded（只记录，不生效）

五、并发设计：全场次锁 vs 席位原子占用

全场次锁（BOOKING_STRATEGY=session）席位原子占用（BOOKING_STRATEGY=seat，默认）
机制应用层 per-session 互斥锁包住「检查+写入」BEGIN IMMEDIATE + 部分唯一索引，冲突面收窄到单个座位
正确性强：整场串行强：唯一索引兜底，最后席位只有一个赢家
并行度同场次全部串行，不同座位也互斥不同座位可并行（行级锁数据库上优势明显）
失败面锁粒度过大，热点场次排队仅同座冲突者收到 409 SEAT_TAKEN
适用需要整场一致快照的操作（如批量换座）在线抢票主路径

本系统默认席位原子占用；占位与确认都在单条 BEGIN IMMEDIATE 事务内完成「复检 + 写入」， SQLite 单写者保证原子性，唯一部分索引保证语义。以下为验收测试实测（8 线程抢最后 1 席 × 3 轮）：

六、关键政策

1. 改期 = 同一活动的新安排

改期只更新 sessions.start_time/end_time 并追加 schedule_history，id 与 public_code 不变， 原预约永远指向同一场次，不会失联。旧票由显式政策处理：migrate 自动迁移并通知；rebook 转「待重订」并释放座位。 改期提交即置 booking_frozen=1，新报名返回 409 BOOKING_FROZEN，运营确认通知发出后手动解冻。

2. 缩减容量：保序、公示、不随机

按 confirm_seq 升序保留先确认者，溢出者置 displaced 并在接口与后台名单中逐人列出（含确认序、座位）， 同时生成 seat_displaced 通知任务。全程无随机撤销。

3. 天气双人确认

天气数据注入只创建 pending 预案（公开状态不变）；运营在后台「确认取消 / 确认顺延 / 驳回」后才改变公开状态。 已取消或已有更晚决定后到达的迟到更新记为 superseded，仅留档。

4. 预留超时

占位默认 120 秒（HOLD_TTL_SECONDS 可调，请求可带 ttl_seconds），读路径惰性清扫； 超时确认返回 410 HOLD_EXPIRED，座位立即回到可选池。

5. 幂等与重复回执

占位、确认均以 idempotency_key 为唯一键：网络重试返回原记录；重复确认返回同一张票（HTTP 200 + idempotent）， 通知任务以 dedupe_key 去重，投递器可安全重跑。

6. 版本与旧响应

服务端：所有变更接受 expected_version，不符返回 409 STALE_VERSION 与当前版本号。 客户端：每次请求带单调序号，乱序到达的旧响应直接丢弃；再按 version 比较，低版本数据不渲染 —— 网页状态永不被旧响应覆盖。
